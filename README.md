# static-lab-conversion

Process and procedure for creating a static version of a network security lab

# How to execute the methodology in a fresh context

## Start with the methodology file and a short instruction such as:

    Use the attached SEED Lab Adaptation Methodology as the governing workflow. Adapt the specified SEED Lab into a complete, non-containerized, role-separated instructional package. Do not begin by writing commands. First produce the source-lab analysis and design brief. Follow the required outputs, filenames, validation checks, and release gates in the methodology.

## Then provide the lab-specific inputs:

    SEED Lab title and source URL;
    historical and current versions to compare;
    course level;
    student prerequisites;
    target Ubuntu release;
    hypervisor;
    VM resource limits;
    expected duration;
    individual or team workflow;
    topics in scope;
    topics explicitly excluded;
    grading requirements;
    Internet availability;
    required student personalization.

The assistant should then work through the methodology in phases, rather than generating the final lab manual immediately.
